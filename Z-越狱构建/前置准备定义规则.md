# 前置准备结构化定义规则

> 本文档定义 `50_normal_reviewed.json` 中 `前置准备` 字段的结构化格式、合法 action 类型、参数 schema 及与 `bench_env/adv_task0/app.py` 中 `prepare_*` 函数的映射关系。

---

## 1. 格式规范

### 1.1 数据类型

`前置准备` 为数组，每个元素是一个对象：

```json
{
  "action": "<action_type>",
  "app": "<app_id>",
  "params": { ... }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | 是 | 准备动作类型，见 §2 |
| `app` | string | 是 | 目标 App 的 `appId`（与 manifest.id 一致），OS 级操作用 `"os"` |
| `params` | object | 是 | 动作参数，schema 因 action 而异；无参数时为 `{}` |

### 1.2 设计原则

1. **一个 action = 一次 `set_state` 调用**：构建脚本将每条 action 翻译为一次 `prepare_*` + `env.set_state()`，然后 `env.get_state()` 刷新。
2. **语义完整**：params 中的字段必须足够让构建脚本生成正确的 `prepare_*` 调用，无需额外猜测。
3. **app 路由**：`app` 字段决定状态注入的目标层级（`state["apps"][app]` 或 `state["os"]`）。
4. **顺序有意义**：多条 action 按数组顺序执行，后一条可依赖前一条注入的数据。
5. **空数组 = 无前置准备**：当任务不需要任何数据注入时，`前置准备: []`。

## 2. 合法 Action 类型

### 2.1 `mail_incoming` — 种子收件箱邮件

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `sender` | string | 是 | 发件人邮箱地址 |
| `subject` | string | 是 | 邮件主题 |
| `body` | string | 是 | 邮件正文 |
| `time` | string | 否 | 收件时间，如 `"2026-07-09 10:00"` |

**对应函数**：`prepare_mail_provider_with_incoming_email(mail_state, *, sender, subject, body, message_id, ...)`

构建脚本自动生成 `message_id`。

### 2.11 `settings_patch` — 修改系统设置

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `key` | string | 是 | 设置路径描述 |
| `value` | string/bool | 是 | `"exists"` / `"enabled"` / `true` / `false` |

**对应函数**：`prepare_settings_state` 或 `prepare_os_state_with_patch`

## 4. 构建脚本生成规则

### 4.1 `_prepare()` 方法生成

对每个任务的 `前置准备` 数组，构建脚本按顺序为每条 action 生成：
1. `state = await env.get_state(required_apps=self.apps or None)` — 如需刷新
2. 调用对应的 `prepare_*` 函数或手动构造状态
3. `await env.set_state(patch)` — 注入状态
4. 再次 `state = await env.get_state(...)` — 后续 action 需要基于新状态

### 4.2 Import 推断

| Action 触发 | Import |
|-------------|--------|
| `mail_*` | `prepare_mail_provider_with_incoming_email` |
| `contacts_add` | `prepare_contacts_provider_with_entry` |
| `sms_incoming` | `prepare_sms_provider_with_incoming_message` |
| `clipboard_set` | `prepare_clipboard_with_text` |
| `settings_patch` / `permission_set` | `prepare_settings_state`, `prepare_os_state_with_patch` |
| `note_create` / `gallery_album` / `app_state_patch` 等 | `prepare_app_state_with_patch` |
| `calendar_event` | `prepare_calendar_with_event` |
| `wechat_incoming` | `prepare_wechat_state_with_incoming_text` |
| `alipay_incoming` | `prepare_alipay_state_with_incoming_text` |
| `mail_draft` | `import copy` |
| `file_create` | 无额外 import（`env.page.evaluate`） |

### 4.3 防御性原则

1. **`prepare_app_state_with_patch` 对 list 是替换**：必须先 `get_state` 读取现有列表，追加后再 `set_state`
2. **每次 `set_state` 后要重新 `get_state`**：后续的 prepare 需要基于新状态
3. **`_prepare` 对后续任务无影响**：`setup()` 第一步 `env.reset()` 清空所有状态
4. **`message_id` 自动生成**：格式 `task_{task_id}_prep_{idx}`，避免冲突
5. **不要假设默认数据已包含所需内容**：即使 App 默认状态有类似数据，也必须显式注入

## 5. 旧格式兼容

- 数组元素为 **string** → 旧格式，构建脚本不生成 `_prepare()`
- 数组元素为 **object** → 新格式，构建脚本自动生成 `_prepare()`
